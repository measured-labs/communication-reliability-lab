# 측정 로그 (Measurement Log)

> 작업당 1행, <1분. 하네스 규칙 증감(core §0-3)은 이 데이터를 근거로 한다.
> 위치: 대상 프로젝트 `docs/measurement-log.md`.

## 스키마 규칙 (파싱 가능성 — 2026-07-03 정비)

- **고정 13열**(아래 표 순서 그대로 — 2026-11-06 v4.3에서 13열 `워커` 추가, 그 전 행은 12열 그대로 read-only). **기존 로그 이행**: 13열 행을 처음 붙일 때 그 파일의 헤더·구분선만 13열로 바꾸고 이전 행은 그대로 둔다 — 파서를 만들 때는 셀 12개 행을 `워커=-`로 읽는다. 열을 합치거나 빼지 않는다 — 없으면 `-`.
- **작업명·내용에 `|`·개행 금지** — `|`는 `∣`(U+2223) 또는 "or"로, 개행은 공백으로. (열 밀림·표 단절 방지)
- **단위 enum**: 총 소요·오버헤드 = `~Nm`(분) 또는 `~Nh`(시간) 정량 우선. 정성(`중`·`큼`)은 정량 불가 시만.
- **stakes enum**: `낮음` / `중간` / `높음` (혼합 표기 금지 — 승격됐으면 최종값 1개).
- **소급/미측정**: 실시간 측정 못 한 필드는 `소급` 또는 `미측정` (빈칸·추정 금지).
- **표는 하나로 유지** — 각주·목록 아래 새 행을 이어붙이지 않는다(표가 쪼개져 파싱 파손).
- 기존 로그(2026-07-03 이전)는 read-only — 이 스키마로 소급 변환하지 않는다(신규 행에만 적용).

- **워커**: `역할 모델×수 토큰합` 묶음을 `·`로 잇는다(예: `구현 Opus×2 300k · 테스트 Opus×1 90k · 리뷰 Opus×1 142k · 탐색 Sonnet×2 60k`). 탐색·구현·테스트 설계·리뷰·요약 워커를 모두 이 한 열에 적는다. 토큰 = 워커 완료 알림 usage의 `subagent_tokens` 합, 없으면 `미측정`. codex는 `codex×N`(토큰 미측정). 메인 세션 토큰은 적지 않는다. 실사용 위임 비용의 사후 관찰 입력이다(core §5 — 탐색 위임은 측정 조건과 도구가 달라서, 구현 위임은 효과의 크기를 재지 않아서 계속 본다).
- **하네스 오버헤드**: 게이트·문서·교차검증에 쓴 시간(작업 자체 제외).
- **검증이 잡은 결함**: 어느 게이트가 잡았는지 명시 (예: "codex 계획검토 1건"). stakes 오판도 이 열에 기록.
- **머지 후 결함 (소급 기입 트리거)**: 배포·GUI·라이브 검증을 이월한 작업은 이 열을 `이월(대기)`로 두고, **다음 세션 재개 시(core §3 세션 재개) 직전 작업의 배포 결과를 1문으로 확인해 소급 기입**한다 — 이 열이 비면 §0.3 개선 루프의 입력이 반쪽이 된다.
- 주기 분석 (**월 1회 또는 사용자 요청 시, 사용자와 함께 리뷰**): 결함·재작업을 줄인 증거 + 저비용 = 유지 / 설명만 그럴듯 + 측정 효과 없음 = 삭제.
